## Für wen der Workshop ist

Der Workshop richtet sich an Entwicklerteams, die schon mit gewachsenem Code arbeiten, also mit echter Fachlogik, Tests, Reviews und Deadlines. Genau dort zeigt sich, ob KI-Werkzeuge helfen oder nur neue Fehlerquellen schaffen.

Typische Ausgangslagen:

- Die Lizenzen sind gekauft, aber jede Person nutzt das Tool anders, manche gar nicht.
- Generierter Code landet ungeprüft im Pull Request, das Review wird zum Engpass.
- Es ist unklar, was das Tool sehen darf und welche Regeln gelten.
- Einzelne sind begeistert, andere skeptisch, und es fehlt eine gemeinsame Arbeitsweise.

## Ablauf des Workshop-Tags

**Grundlagen:** Wie arbeiten KI-Agenten, was können sie gut und wo liegen ihre typischen Fehler? Warum Kontext wichtiger ist als der perfekte Prompt und wie Projektregeln dem Agenten eure Konventionen beibringen.

**Live-Demo an einer echten Aufgabe:** Ich setze vor dem Team eine Aufgabe aus eurem Backlog um, von der Planung über die Umsetzung in kleinen Schritten bis zu Tests und Review. Dabei wird sichtbar, wo der Agent Zeit spart und wo ich eingreife.

**Übungen im eigenen Repository:** Die Teilnehmenden arbeiten in Paaren an eigenen Aufgaben. Ich gehe herum, beantworte Fragen und zeige Kniffe direkt am Problem.

**Gemeinsame Regeln:** Zum Abschluss halten wir fest, wie ihr als Team mit KI arbeiten wollt: Projektregeln für den Agenten, Anforderungen an Pull Requests mit generiertem Code und was das Tool sehen darf.

## Begleitung im Anschluss

Nach dem Workshop-Tag beginnt der eigentliche Wandel im Alltag. In der Begleitung arbeite ich zwei bis vier Wochen mit eurem Team am echten Backlog mit, im Pairing, in Reviews und bei der Verfeinerung der Projektregeln. So werden aus den Übungen feste Gewohnheiten, und Fragen, die erst nach ein paar Tagen auftauchen, landen nicht im Leeren.

## Regeln, Setup und Datenschutz

Damit KI im Team funktioniert, braucht es mehr als eine Lizenz:

- **Projektregeln für den Agenten:** Architektur, Namenskonventionen, Test-Strategie und verbotene Muster, festgehalten im Repository, damit jeder Agent sie kennt.
- **Review-Prozess:** Wer generierten Code einreicht, muss ihn verstanden haben. Wir legen fest, wie das im Pull Request sichtbar wird.
- **Datenschutz:** Welche Dateien und Daten das Tool lesen darf, welche Einstellungen das absichern und was in den Lizenzbedingungen steht.

## Meine Arbeitsweise

Ich entwickle selbst täglich mit KI-Agenten, aber die Verantwortung für den Code bleibt bei mir: erst denken, dann generieren, in kleinen prüfbaren Schritten, mit Tests als Sicherheitsnetz und jeder Zeile im Review. Genau diese Arbeitsweise gebe ich im Workshop weiter. Es geht nicht darum, möglichst viel Code generieren zu lassen, sondern darum, schneller zu gutem Code zu kommen.
